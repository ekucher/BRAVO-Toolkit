# Правила AI-розробки BRAVO-Toolkit

## Пріоритет джерел
Перед змінами перевіряй поточний стан GitHub, документацію, контракти та CI. Не вважай попередні звіти актуальним станом. Уся документація проєкту — українською.

## Автоматичне делегування
Користувач не повинен вибирати модель. Основна сесія використовує Sonnet; для вузьких задач залучай спеціалізованих агентів з `.claude/agents/`. Делегування — рекомендація, не заміна обов'язкових CI-gates.
- repository-analyst (Haiku): read-only аналіз репозиторію, Issues і логів.
- documentation (Haiku): документація та звіти.
- developer (Sonnet): код і локальні перевірки.
- test-engineer (Sonnet): незалежна перевірка тестів і регресій.
- architect (Opus): складні контракти, архітектура, критичні зміни.
- security-reviewer (Opus): security, backup/restore, SYSTEM та integrity.

## Класифікація ризику
LOW: документація, аналітика; MEDIUM: локальні зміни коду; HIGH: міжмодульні контракти; CRITICAL: backup/restore, конфігурація, інсталятор, SYSTEM/Scheduler, автентифікація, цілісність і безпека. Для HIGH/CRITICAL залучай architect перед реалізацією; для CRITICAL — security-reviewer та незалежне рев'ю.

## Якість і дозволи
Не змінюй production-код без перевірки Windows PowerShell 5.1, відповідних Windows support tiers, контрактів та RED/GREEN тестів. Docs-only не потребує production self-test, якщо не змінено виконувані файли або CI-контракти. Не оголошуй CI зеленим без перевірки результатів і логів. Не обходь gates. Не виконуй merge без належної авторизації. Для незалежного рев'ю спочатку спробуй Codex MCP. Якщо Codex недоступний через ліміти, 429, quota, тайм-аут або збій інтеграції — автоматично переходь до окремого Claude Opus reviewer; якщо Opus недоступний — до окремого Claude Sonnet reviewer. Не повторюй безкінечно запити Codex і не запитуй користувача про вибір моделі. Reviewer не повинен бути автором змін або повторно використовувати його висновки як незалежний доказ. Зафіксуй причину fallback і використану модель у PR. Недоступність Codex сама по собі не блокує процес, але відсутність обов'язкового незалежного рев'ю, P0–P2, невдалі CI або недостатні докази можуть блокувати merge. Не припускай, що MCP налаштований лише через наявність інструкції.
