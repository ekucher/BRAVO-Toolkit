# Оновлення парку 5.2.4 → 5.2.6 — операторський runbook

Для серверів лінії 5.2 (5.2.4, 5.2.5). Оновлення виконується **однією дією**:
подвійний клік на `UPDATE-BRAVO52.cmd` і підтвердження UAC. Решту робить
скрипт: знаходить комплект, перевіряє архів, робить backup, оновлює, перевіряє
і за потреби сам відкочує.

## 1. Навіщо оновлювати

`5.2.4` має дефект #335: retention може видалити повну (COMPLETE) резервну
копію як «невдалу» — без попередження і навіть при `enableArchiveDeletion =
$false`. Виправлено в `5.2.5`; `5.2.6` — той самий runtime-код, змінено лише
документацію. Повний перелік змін і змінена поведінка — у нотатках
[Release 5.2.5](https://github.com/ekucher/BRAVO-Toolkit/releases/tag/v5.2.5) і
[5.2.6](https://github.com/ekucher/BRAVO-Toolkit/releases/tag/v5.2.6).

Поки сервер на 5.2.4, тимчасова мітигація #335 — рядок у `BRAVO.local.config`:

```powershell
'enableFailedArchiveDeletion' = $false
```

Після оновлення скрипт прибере його сам (див. розділ 6).

## 2. Пакет оновлення

Скопіюйте на сервер **в окремий каталог поза комплектом**, напр.
`C:\Temp\BRAVO_UPDATE_PACK` (усередині каталогу комплекту скрипт відмовиться
працювати):

| Файл | Обов'язковий |
|---|---|
| `UPDATE-BRAVO52.cmd` | так |
| `Update-BRAVO52.ps1` | так |
| `Update-BRAVOServer.ps1` | так |
| `BRAVO.Deploy.ReleaseGate.ps1` | так |
| `BRAVO.Deploy.Rollback.ps1` | так |
| `BRAVO-Toolkit-5.2.6.zip`, `BRAVO-Toolkit-5.2.6.zip.sha256`, `release-manifest.json` | лише для сервера без доступу до GitHub — усі три, з [Release 5.2.6](https://github.com/ekucher/BRAVO-Toolkit/releases/tag/v5.2.6) |

Якщо архіву поруч немає, скрипт завантажить усі три ассети з GitHub сам.
Очікуваний SHA-256 архіву (скрипт звіряє його сам):

```
d476f87652fa9c6614383371700102088bf229cf5a87f0e2e01e59e82e6bd4e2
```

## 3. Порядок парку

```
перевірка (крок 1, нічого не змінює, усі сервери)
    -> пілотний сервер (крок 2)
    -> перша доба на пілоті (крок 3)
    -> решта парку (крок 4)
```

Оновлюйте вдень, коли нічні завдання не виконуються: якщо якесь завдання
`\BRAVO\` працює, скрипт зупиниться і нічого не змінить.

## 4. Крок 1 — перевірка (нічого не змінює)

У консолі в каталозі пакета, права адміністратора не потрібні:

```bat
UPDATE-BRAVO52.cmd -CheckOnly
```

Скрипт покаже каталог комплекту, встановлену версію, звідки візьме архів і чи
знайдено мітигацію #335. Код `0` — сервер готовий; інакше в рядку `ЗУПИНЕНО:`
пояснення, що виправити.

Поріг вільного місця й стан завдань (preflight) перевіряються вже під час
оновлення, з правами адміністратора; повторно — як для 5.2.4 (runbook
`BRAVO_524_FLEET_ROLLOUT_RUNBOOK_20260913.md`, розділи 4–5).

## 5. Крок 2 — пілотний сервер

Подвійний клік на `UPDATE-BRAVO52.cmd` → підтвердити UAC → дочекатися рядка
`ГОТОВО` → Enter.

Що відбувається по порядку:

1. каталог комплекту — за завданнями Планувальника `\BRAVO\` (або
   `C:\Program Files\BRAVO-Toolkit`); інший шлях — `-RuntimeRoot "D:\..."`;
2. перевірка версії: оновлюється лише 5.2.4+ вгору (5.2.0–5.2.3 — лише з
   `-AllowUntestedSource`; новіші й інші лінії — відмова);
3. preflight: поріг вільного місця, жодне завдання не виконується;
4. архів: локальний або завантажений, SHA-256, `release-manifest.json`
   (провенанс), канал `stable`;
5. backup комплекту копіюванням у `<каталог>.old_<версія>_<час>`;
6. копіювання поверх; `BRAVO.config`, `BRAVO.local.config`,
   `Tools\TOOLS_INTEGRITY.json`, `WinSCP.ini`, `LOGS\` і каталоги даних не
   чіпаються;
7. гейти: `VERSION.json` = 5.2.6, guard `0`, перереєстрація завдань,
   `BRAVO_SETUP -ValidateOnly`;
8. провал гейта — **автоматичний відкат** з backup;
9. прибирання мітигації #335 (розділ 6).

Журнал і підсумок: `%ProgramData%\BRAVO\Upgrade\upgrade-<час>.log` і
`upgrade-summary-<час>.json` (версії до/після, результат, код Update-BRAVOServer,
стан мітигації).

### Коди завершення

| Код | Значення | Дія |
|---|---|---|
| 0 | оновлено (або вже 5.2.6) | крок 3 |
| 1 | зупинено до змін, або гейт провалився і відкат успішний | прочитати `ЗУПИНЕНО:` / журнал, виправити, повторити |
| 2 | **відкат не вдався** | не запускати BRAVO; ручний відкат (розділ 9), backup — у журналі |
| 3 | оновлено, але мітигацію #335 треба прибрати вручну | розділ 6 |

## 6. Мітигація #335

Якщо в `BRAVO.local.config` є рядок `'enableFailedArchiveDeletion' = $false`,
після успішного оновлення скрипт:

1. зберігає копію файлу в `%ProgramData%\BRAVO\Upgrade\BRAVO.local.config.before-335-<час>`;
2. видаляє лише цей рядок (кодування й решта ключів без змін);
3. перевіряє `BRAVO_SETUP -ValidateOnly`; за провалу повертає файл з копії (код `3`).

Якщо рядок змішаний з іншим ключем або файл не розбирається, скрипт нічого не
змінює і завершується кодом `3` — приберіть рядок вручну.
Залишити мітигацію свідомо: `UPDATE-BRAVO52.cmd -KeepMitigation335`.

Значення `$false`, задане не в `BRAVO.local.config`, а в самому `BRAVO.config`,
скрипт не змінює — поверніть там `$true` вручну.

## 7. Крок 3 — перша доба на пілоті

Не розкочуйте далі, доки не побачите нічні Archive, Health і Maintenance.
Журнали — у `<каталог комплекту>\LOGS`:

- `BRAVO_ARCHIV_*.log`: `=== ПОЧАТОК РОБОТИ СКРИПТА BRAVO_ARCHIV v.5.2.6 ===`,
  `Результат: УСПIШНО`, рядок `Аудит retention: ...`;
- `BRAVO_MAINTENANCE_*.log`: `=== СТАТУС: ... ===` без помилок;
- Health: без коду `90`.

Що тепер штатно і **не** є проблемою:

- Health більше не пише WARNING про давнє оновлення Windows;
- WARNING `Пошкоджена резервна копія ...` — копію пошкоджено, але її більше не
  видаляють; розберіться з причиною;
- Maintenance з `componentSettings.SFTP.Enabled = $false` завершується кодом
  `10` — відома проблема, є і в 5.2.4.

Нові коди, які може побачити моніторинг: Recovery на ночі із заблокованою
реставрацією — `10`; виняток після запуску `bravocmd.exe` — `43`
(див. нотатки 5.2.5, #438/#477).

## 9. Відкат

**Автоматичний** — виконує сам скрипт при провалі гейта (код `1`).

**Ручний**, якщо проблему виявлено пізніше (шлях backup — у журналі):

```powershell
$runtime = 'C:\Program Files\BRAVO-Toolkit'
$backup  = 'C:\Program Files\BRAVO-Toolkit.old_5.2.4_20261029_140000'   # свій шлях

Get-ScheduledTask -TaskPath '\BRAVO\' | Where-Object State -eq 'Running'   # має бути порожньо
robocopy $backup $runtime /E /R:2 /W:2 /XD LOGS
Push-Location $runtime; .\BRAVO_RUNTIME_GUARD.ps1; $LASTEXITCODE; Pop-Location
.\BRAVO_SETUP.ps1 -Action Scheduler
```

Якщо 5.2.6 уже відпрацювала хоч одну ніч, guard 5.2.4 блокує відкат кодом `35`
(захист від відкату версії). Свідомий відкат — з `$env:BRAVO_ALLOW_DOWNGRADE = '1'`
у тій самій консолі. Лічильник повторів реставрації (#438) 5.2.4 не читає — він
буде втрачений.

**Не перейменовуйте каталог комплекту** ні при оновленні, ні при відкаті
(ACL `BRAVO_TASKS_INSTALL`, guard `33`).

## 10. Відомі проблеми 5.2.6

#422 (мітигація: `'maintenanceSettings.Retention.FailedArchiveDays' = 365` у
`BRAVO.local.config`), #300, #501, retention після перенесення сховища, VSS при
ручному запуску з профілю з не-ASCII шляхом, код `10` Maintenance без SFTP —
подробиці в нотатках Release 5.2.5.
