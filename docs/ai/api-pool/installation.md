# Anthropic API Agent Pool v1: встановлення

Пул є інструментарієм агентів і не входить до production-runtime BRAVO. Його не потрібно встановлювати на виробничі хости; призначений вузол: робоче місце або dev/test-хост, з якого працюють агенти.

## 1. Вимоги

- Windows PowerShell 5.1 (`powershell.exe`). PowerShell 7 не підтримується і не перевірявся.
- Обліковий запис звичайного користувача. Елевація не потрібна.
- Каталог `Tools/ApiPool` з комплекту репозиторію (заморожений набір файлів, див. `architecture.md`).
- У v1 мережевий доступ до Anthropic не потрібен і не використовується (офлайн-збірка).

## 2. Розташування і шляхи

| Об'єкт | Шлях |
|---|---|
| код і конфігурація | `Tools/ApiPool` |
| типові налаштування | `Tools/ApiPool/config/apipool.defaults.json` |
| реєстр моделей і цін | `Tools/ApiPool/config/models.json` |
| корінь стану (типовий) | `%LOCALAPPDATA%\BRAVO\ApiPool\state` |
| файл облікових даних | `%LOCALAPPDATA%\BRAVO\ApiPool\anthropic-api-key.dpapi` |
| метадані ротації | `<файл облікових даних>.meta.json` |
| попередній ключ | `<файл облікових даних>.previous` |

Типові шляхи розв'язує лише точка входу `Invoke-ApiPool.ps1`; модулі шлях самі не вибирають. Корінь стану й шлях до секрету проходять перевірку `Assert-ApiPoolSafePath`: абсолютний локальний шлях, не UNC і не префікс пристрою, не в `C:\ProgramData\BRAVO`, не всередині репозиторію, без reparse-point серед наявних предків. Порушення дає `STATE_PATH_FORBIDDEN`.

Весь стан бюджету (`$60`) прив'язаний до одного канонічного кореня стану. Не створюйте кілька коренів: кожен має власний журнал і власний ліміт.

## 3. Налаштування

Типові значення (`config/apipool.defaults.json`): `mode = offline`, `budgetUsd = 60`, `perJobUsd = 2`, `maxConcurrency = 2`. Перелік усіх ключів і діапазонів: `budget.md`, розділ 1. Невідомі ключі відхиляються (`CONFIG_UNKNOWN_KEY`). Локальні зміни вносяться через окремий файл перевизначення (параметр `-ConfigPath` CLI), що накладається на типові значення.

Статус: реалізація в процесі (W4); звірити з кодом перед публікацією. (Параметр `-ConfigPath` та точка входу реалізуються в W4; модуль `Read-ApiPoolConfig` підтримує основний файл і файл перевизначення вже зараз.)

Значення `mode = live` у v1 завжди відхиляється (`LIVE_DISABLED_IN_BUILD`) і не вмикає мережевої поведінки.

## 4. Облікові дані (для підготовки до LIVE; офлайн вони не потрібні)

Файл містить вихід DPAPI зі сферою `CurrentUser` для UTF-8 байтів ключа без entropy. Вимоги до значення: не менше 8 символів, без пробільних і керувальних символів; кінцеві пробільні символи (наприклад, завершальний перевід рядка) обрізаються. Інакше `CREDENTIAL_INVALID_FORMAT`.

Створення і ротація виконуються лише командою `credential-rotate`, що читає ключ через `Read-Host -AsSecureString` (ключ не передається аргументом і не потрапляє в історію командного рядка). Ротація зберігає попередній файл як `.previous`, пише `.meta.json` з `rotatedAtUtc` і `fingerprint` (8 hex-символів SHA-256) та виставляє ACL лише для поточного користувача і SYSTEM.

Статус: реалізація в процесі (W4); звірити з кодом перед публікацією. (Команда `credential-rotate` реалізується в W4; модульна функція `Set-ApiPoolCredential` реалізована.)

Файл не можна переносити між обліковими записами або машинами: DPAPI `CurrentUser` його там не розшифрує (`CREDENTIAL_UNREADABLE`).

## 5. Ініціалізація бюджету

Журнал створюється командою `budget-init` (запис `INIT` з лімітом у micro-USD, `budgetUsd * 1 000 000`). Команда ідемпотентна: повторний виклик із тим самим лімітом нічого не змінює; з іншим лімітом відхиляється (`CONFIG_INVALID`). До ініціалізації статус бюджету `UNINITIALIZED`, а резервування відхиляються (`LEDGER_UNINITIALIZED`).

Статус: реалізація в процесі (W4); звірити з кодом перед публікацією.

```powershell
powershell.exe -NoProfile -File Tools\ApiPool\Invoke-ApiPool.ps1 budget-init
```

## 6. Перевірка офлайн-режиму

Статус: реалізація в процесі (W4); звірити з кодом перед публікацією.

Після встановлення переконайтеся, що збірка офлайн:

```powershell
powershell.exe -NoProfile -File Tools\ApiPool\Invoke-ApiPool.ps1 capabilities
powershell.exe -NoProfile -File Tools\ApiPool\Invoke-ApiPool.ps1 health
```

Очікується: режим `offline`, відсутній live-транспорт, справний або ще неініціалізований журнал бюджету. Обидві команди повертають однорядковий JSON `{ok, code, data}` і код завершення 0.

Незалежно від CLI, офлайн-властивості збірки перевіряє набір тестів (`testing.md`):

```powershell
powershell.exe -NoProfile -File Tools\ApiPool\tests\Invoke-ApiPoolTests.ps1 -Suite NetworkIsolation
```

## 7. Оновлення

Оновлення виконується копіюванням нової версії `Tools/ApiPool` поверх старої без `/MIR`. Тому файли `.ps1` і `.psm1`, що постачалися раніше, не перейменовуються і не видаляються (див. `architecture.md`, розділ 2.1). Стан у корені стану (`budget/`, `ratelimit/`, `jobs/`) та файл облікових даних оновленням не змінюються.

## 8. Видалення

Видаліть каталог `Tools/ApiPool` і, за потреби, `%LOCALAPPDATA%\BRAVO\ApiPool`. Перед видаленням кореня стану збережіть `budget\ledger.jsonl` як облікові докази. Якщо ключ існував, відкличте його в Anthropic Console (не лише видаліть файл).
