# Anthropic API Agent Pool v1: діагностика

Кожна помилка має код. У виключеннях він міститься в `FullyQualifiedErrorId` (`ApiPool.<CODE>`) і на початку повідомлення (`[<CODE>] ...`). Адаптер частину кодів повертає в результаті (`Code`), а не кидає: у таблицях це позначено. Усі повідомлення пропускаються через редагування секретів.

Перевірено пошуком у модулях `Tools/ApiPool/modules`: усі коди розділів 1-5 присутні в коді. Код `LEDGER_WRITE_FAILED`, згаданий у проєктних нотатках, у коді відсутній: такого коду немає. Збої запису журналу виходять як звичайні виключення .NET; адаптер перетворює їх на `INTERNAL_ERROR`.

## 1. Конфігурація і шляхи

| Код | Причина | Дія оператора |
|---|---|---|
| `CONFIG_INVALID` | Файл конфігурації або реєстру моделей відсутній, не є коректним JSON, ключ має неправильний тип чи вихід за діапазон, `perJobUsd` більше `budgetUsd`, `mode` не `offline`/`live`, або `INIT` повторено з іншим лімітом | Виправте файл за повідомленням (ключ названо в тексті); діапазони в `budget.md`, розділ 1 |
| `CONFIG_UNKNOWN_KEY` | У конфігурації невідомий ключ (регістр важливий) | Видаліть або виправте ключ; допустимі ключі в `budget.md` |
| `STATE_PATH_FORBIDDEN` | Корінь стану або шлях секрету порожній, з `%VAR%`, відносний, UNC/`\\?\`/`\\.\`, у `C:\ProgramData\BRAVO`, усередині репозиторію або через reparse-point | Вкажіть абсолютний локальний шлях у профілі користувача, наприклад у `%LOCALAPPDATA%\BRAVO\ApiPool` |
| `LIVE_DISABLED_IN_BUILD` | Конфігурація має `mode = live`, або викликано `New-ApiPoolHttpTransport` | У v1 live неможливий. Поверніть `mode = offline`. Перехід: `operations.md`, розділ 7 |

## 2. Облікові дані

| Код | Причина | Дія оператора |
|---|---|---|
| `CREDENTIAL_NOT_FOUND` | Файл облікових даних відсутній або порожній, немає `SecretPath`, немає `.previous` для відновлення | Створіть ключ командою `credential-rotate`; перевірте шлях |
| `CREDENTIAL_UNREADABLE` | Файл не читається або DPAPI не розшифровує його для поточного користувача (інший користувач, інша машина, пошкодження) | Запустіть від потрібного користувача; за потреби виконайте ротацію ключа заново |
| `CREDENTIAL_INVALID_FORMAT` | Розшифроване значення коротше за 8 символів, містить пробіли чи керувальні символи (початкові пробіли не обрізаються) | Введіть ключ повторно через `credential-rotate` |
| `CREDENTIAL_ROTATION_FAILED` | Не вдалося записати файл, `.previous`, `.meta.json` або виставити ACL | Перевірте права й вільне місце, перегляньте тип виключення в повідомленні, повторіть ротацію; перевірте, що старий ключ ще дійсний |

## 3. Ціни, запит, використання

| Код | Причина | Дія оператора |
|---|---|---|
| `PRICING_UNKNOWN` | Модель відсутня в реєстрі, вимкнена (`enabled: false`, зокрема haiku), має невалідні ціни (`PRICING_INVALID` лише маркер запису, не кидається), або промпт перевищує найвищий рівень | Використайте дозволену модель; для невалідного запису виправте `models.json`; зменште промпт |
| `USAGE_INVALID` | У `usage` відповіді поле відсутнє, не число, від'ємне чи нецілочисельне (адаптер перетворює це на `RESPONSE_MALFORMED` і лишає резервування в обліку) | Збережіть `requestId`, звірте витрату в Console (розділ `budget-reconcile`) |
| `REQUEST_INVALID` | Некоректний запит чи параметр: порожній текст, невірні ролі, першим не `user`, `max_tokens` менше 1, порожній `JobId`, порожня причина, від'ємна сума | Виправте запит за повідомленням |
| `REQUEST_FORBIDDEN_FIELD` | У запиті поле поза allowlist (`tools`, `tool_choice`, `mcp_servers`, `container`, `temperature`, `metadata` тощо) або нетекстовий блок | Приберіть поле; пул приймає лише `model`, `max_tokens`, `system`, `messages` |
| `MAX_TOKENS_EXCEEDS_MODEL` | `max_tokens` більший за `maxOutputTokens` моделі | Зменште `max_tokens` |
| `LINE_INVALID` | Спроба дописати до журналу рядок із переносом рядка (внутрішня помилка програми) | Повідомте розробників; журнал не змінено |

## 4. Журнал, замки, бюджет

| Код | Причина | Дія оператора |
|---|---|---|
| `LEDGER_LOCK_TIMEOUT` | Замок `ledger.lock` не отримано за таймаут (інший процес довго тримає його) | Повторіть; перевірте, чи не завис інший процес пулу. Замок звільняє ОС при завершенні процесу, файл замка вручну не видаляйте. Адаптер повертає цей код у результаті |
| `RATELIMIT_LOCK_TIMEOUT` | Замок rate limit моделі не отримано за 5 с | Повторіть; перевірте процеси пулу. Адаптер повертає код у результаті |
| `LEDGER_UNINITIALIZED` | Журнал ще не створено | Виконайте `budget-init` |
| `LEDGER_CORRUPT` | Журнал пошкоджено (парсинг, розрив ланцюга, прогалина `seq`, невідомий тип, повторний `INIT`, порожній файл) | `operations.md`, розділ 5: `budget-repair` лише для обірваного хвоста; інакше вручну |
| `BUDGET_EXHAUSTED_GLOBAL` | Нове резервування перевищило б глобальний ліміт | Дочекайтеся звіряння осиротілих резервувань або збільшіть ліміт лише рішенням власника; адаптер повертає код у результаті |
| `BUDGET_EXHAUSTED_JOB` | Нове резервування перевищило б ліміт завдання (мінімум з усіх лімітів для завдання) | Розбийте завдання або зменшіть запит; адаптер повертає код у результаті |
| `BUDGET_STOPPED` | Активна аварійна зупинка (маркер, запис `STOP` або похідний стан) | `budget-status` покаже `EmergencyStop.Source` і причину; усуньте причину й виконайте `budget-clear` (розділ 3 `operations.md`) |
| `BUDGET_OVERRUN` | Фактична вартість перевищила резерв; витрату зафіксовано, увімкнено зупинку. Повертається в результаті, не кидається | Перевірте ціни й запис `OVERRUN`; звірте з Console; зніміть зупинку лише після з'ясування |
| `RESERVATION_NOT_FOUND` | Невідомий `ReservationId` | Візьміть ідентифікатор з `budget-status` |
| `RESERVATION_STATE_INVALID` | Операція недопустима для поточного стану резервування (наприклад, скасування вже зафіксованого) | Перегляньте стан у `budget-status`; повторювати не потрібно |
| `SLOT_TIMEOUT` | Жоден слот конкурентності не звільнився за `min(requestTimeoutSec, 30 с)` | Повторіть пізніше або збільште `maxConcurrency` (до 16); перевірте завислі процеси пулу. Повертається в результаті |

## 5. Відповіді API і транспорт

| Код | Причина | Дія оператора |
|---|---|---|
| `RATE_LIMITED` | HTTP 429 | Адаптер повторює з урахуванням `Retry-After` (обмеженого `maxRetryAfterSec`); зменште паралелізм |
| `API_OVERLOADED` | HTTP 529 | Повтор виконує адаптер; за стійкої появи повторіть пізніше |
| `API_SERVER_ERROR` | HTTP 500 або 503 | Повтор виконує адаптер |
| `API_CLIENT_ERROR` | HTTP 400, 402, 404, 413, 422; не повторюється; резервування скасовано | Виправте запит (модель, розмір); код 402 означає проблему з обліковим записом чи біллінгом: зверніться до власника |
| `API_AUTH_FAILED` | HTTP 401 або 403; не повторюється | Перевірте ключ у Console; виконайте `credential-rotate` |
| `TRANSPORT_TIMEOUT` | Таймаут транспорту. При `sent=false` резервування скасовано, при `sent=true` або без ознаки лишається `UNRECONCILED` | При `UNRECONCILED` виконайте звіряння (`operations.md`, розділ 4) |
| `TRANSPORT_ERROR` | Збій транспорту; у fake-транспорті також вичерпана черга (`sent=false`) | Як для `TRANSPORT_TIMEOUT`; у тестах додайте відповіді в чергу |
| `RESPONSE_MALFORMED` | Статус 200 з некоректним тілом (не `message`, немає `stop_reason`, неприйнятний `usage`) або невідомий HTTP-статус; резервування лишається `UNRECONCILED` | Збережіть `requestId`; звірте витрату в Console |
| `RETRY_EXHAUSTED` | Вичерпано `retry.maxAttempts`; в `Details.lastCode` код останньої помилки | Повторіть пізніше; перевірте, чи не лишилися `UNRECONCILED` |
| `CANCELLED` | Завдання скасовано маркером до спроби або під час очікування | Очікувана поведінка |
| `INTERNAL_ERROR` | Некоректна внутрішня конфігурація: невідомий або відсутній транспорт, неправильно задана відповідь fake, збіжність очікування rate limit не досягнута; також будь-яка непередбачена помилка без власного коду | Перегляньте повідомлення; якщо після резервування, перевірте `budget-status` на осиротіле резервування |

## 6. Коди керування завданнями (реалізація в процесі)

Статус: реалізація в процесі (W4); звірити з кодом перед публікацією.

Цих кодів немає в модулях у цій гілці. Таблицю складено за проєктом.

| Код | Причина | Дія оператора |
|---|---|---|
| `MODE_OFFLINE` | `run` у офлайн-збірці: live-транспорт не постачається | Очікувана поведінка v1 |
| `POOL_DISABLED` | Пул вимкнений; `orchestrate` повертає `fallback` з цією причиною | Продовжуйте без пулу |
| `JOB_NOT_FOUND` | Невідомий `JobId` | Перевірте ідентифікатор |
| `JOB_BUSY` | Завдання виконується іншим процесом (замок завдання зайнятий) | Дочекайтеся завершення |
| `JOB_TERMINAL` | Завдання в термінальному стані; перезапис заборонено | Створіть нове завдання |
| `IDEMPOTENCY_CONFLICT` | Той самий ключ з іншим навантаженням | Змініть ключ або поверніть початкове навантаження |
| `RESUME_NOT_ALLOWED` | Відновлення недопустиме з поточного стану | Перегляньте стан завдання |
| `RESUME_LIMIT` | Вичерпано межу відновлень | Створіть нове завдання |
| `HANDOFF_MALFORMED` | Вихід агента не містить коректного HANDOFF | Перегляньте результат; повторіть за потреби |

## 7. Загальні перевірки

1. `budget-status`: стан, осиротілі резервування, джерело зупинки.
2. `health`: режим і конфігурація.
3. Запуск тестів: `tests\Invoke-ApiPoolTests.ps1` (див. `testing.md`).
4. Журнал і маркер не редагуйте вручну; фіксуйте `requestId`, `ReservationId` і час для звіряння.
