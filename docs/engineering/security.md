# Правила безпеки

Оцінюй вплив на безпеку для кожного зовнішньо досяжного чи привілейованого
шляху виконання коду.

Перевіряй, де застосовно:

- ін'єкції;
- path traversal;
- виконання команд;
- небезпечну десеріалізацію;
- обхід автентифікації й авторизації;
- SSRF;
- XSS і CSRF;
- небезпечне завантаження файлів;
- розкриття секретів;
- небезпечні тимчасові файли;
- гонки навколо прав доступу;
- небезпечні значення за замовчуванням.

Вимоги:

- валідуй недовірений вхід на межах довіри;
- параметризуй запити до баз даних;
- не будуй shell-команди з недовірених рядків;
- використовуй мінімальні привілеї;
- не логуй креденшели чи токени;
- не вимикай перевірку сертифікатів як обхідний шлях;
- зберігай наявні перевірки доступу, якщо задача явно не змінює політику.

Безпекова поведінка мусить відмовляти безпечно й давати корисну
діагностику без розкриття секретів.

## Межі безпеки BRAVO

- SFTP-з'єднання BRAVO вимагають явної перевірки/pinning SSH host key; не
  додавай fallback-ів accept-any-host-key чи інтерактивної довіри.
- Автентифікація SFTP паролем — поточна підтримувана модель розгортання;
  не замінюй її ключами попутно.
- Не логуй значень креденшелів і URI, що містять секрети. Ідентифікатори
  цілей Credential Manager можна логувати, коли це операційно корисно.
- Перевірку цілісності runtime/інструментів не можна вимикати чи
  послаблювати лише для того, щоб пройшов деплой чи тест. Спершу з'ясуй
  причину неочікуваної зміни.
- Деструктивна runtime-поведінка мусить відмовляти в закритий стан, коли
  не можна встановити володіння, обсяг, шлях, віддалену ідентичність чи
  цілісність.

## Секрети й публікація

- Ніколи не розкривай і не комітуй паролі, токени, приватні ключі,
  креденшели, webhook-секрети чи production-секрети.
- Не публікуй у репозиторії, PR, issue, коментарях, release notes і
  повідомленнях комітів посилань на приватні переписки чи чати.
  Для простежуваності використовуй SHA коміта, номер issue/PR чи
  ідентифікатор знахідки.
- Реальні ідентифікатори середовищ заборонені — див. розділ «Заборона
  реальних ідентифікаторів» у `docs/engineering/README.md`.
