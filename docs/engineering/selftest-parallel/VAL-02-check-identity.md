# VAL-02: ідентичність перевірок і модель еквівалентності

Статус: характеризація (лише документація, без змін коду). Доповнює
[VAL-01](VAL-01-suite-inventory.md) (інвентар suite і числа). Закриває частину
VAL-02 «characterization baseline Full» з
`docs/design/BRAVO_VALIDATION_ARCHITECTURE.md`. Мета workstream: рішення
власника OD-32 «c, поетапно» (спершу швидкий non-required сигнал, потім
заміна required check лише за умов). Цей документ нічого не вмикає й не
дублює `ROADMAP.md`.

Усі твердження стосуються об'єкта `3d441d4e`
(`3d441d4eaeba5640c2da0250e4ac7e0dbc569ead`) і застаріють разом із ним.
Числа, їхні файли й SHA-256: у VAL-01 (розділ «Джерела й хеші»).

## Ідентичність перевірки

- Перевірка виконується через `Test-BRAVOCondition ... -Name "<ID>"`.
  **ID перевірки = значення `-Name`** (формат `Група/Назва`). Окремого реєстру
  чи нумерації немає.
- Результат перевірки: `PASS` або `FAIL`. Третій стан `[НЕДОСТУПНО]`
  (UNAVAILABLE) не входить у лічильники й не змінює exit 0 та маркер
  `SELF-TEST PASSED` (за `02-COVERAGE-AUDIT.md`); код, що примушував би
  «0 `[НЕДОСТУПНО]`», на `3d441d4e` відсутній.
- Один ID дає один рядок результату; у еталонному Full дублікатів ID немає
  (`duplicate_id_groups` = 0, 4 172 унікальні `[PASS]`, VAL-01).
- ID бувають статичні (літерал у коді), параметризовані (шаблон із
  підстановкою в циклі) і динамічні (залежать від дерева файлів, середовища,
  даних). Динамічні ID дають runtime-only множину (607) і ускладнюють
  порівняння за статичним аналізом. Приклад із звіту: `Parser/<ім'я файлу>`
  народжується перебором дерева, тому залежить від дерева PR.
- Не покладатися на stdout як джерело ID/результату: у зеленому лозі є
  банер із `[FAIL]` і вкладені `[PASS]` дочірніх прогонів (за
  `02-COVERAGE-AUDIT.md`). Структурований артефакт результату станом на
  `3d441d4e` не існує (рішення власника OD-06, не реалізовано).

## Контекст K

Порівняння ID має сенс лише в межах одного контексту прогону **K**: sha,
образ і версія runner-а, event/ref, права адміністратора, наявність
git/`.git`, версія PowerShell, режим мови, розкладка дисків, наявність 7za та
WinSCPnet. Частина ID залежить від K (env-залежні; число «52» і «45
EnvironmentLimitation-сайтів» цитується зі звіту, див. VAL-01, не перевірено
за `data/`). Тому ID з різних K не порівнюються.

## Модель еквівалентності

Нехай для пари (sha, K) прогін P породжує мультимножину
`M(P) = { (Name, Result) }`: кожна перевірка це пара ім'я та результат, ідентичні
пари враховуються з кратністю.

**Еталон** `F(sha, K)` = `M` повного (Full) прогону `BRAVO_SELF_TEST.ps1` без
`-Suite` на тому самому sha і в тому самому K.

**Кандидат** (наприклад, об'єднання `-Suite` worker-ів) еквівалентний еталону,
якщо на тому самому (sha, K) виконуються всі умови:

1. `M(кандидат) = F(sha, K)` як мультимножини пар (Name, Result): ті самі
   імена, ті самі результати, ті самі кратності. Порядок не враховується;
   розбиття й порівняння за ID або suite, ніколи за позицією.
2. Кожне виконання кандидата має `Result = PASS` для всіх пар, що є PASS в
   еталоні; жодного `FAIL`.
3. Кількість `[НЕДОСТУПНО]` у кандидаті дорівнює 0 (так само має бути й в
   еталоні, інакше еквівалентність не визначена для цього K).
4. Union suite-складових покриває X_full: обидва Full-only ID (VAL-01) присутні
   з PASS, або з окремого Full-shaped прогону, або за явним рішенням власника
   (OD-03). Інакше `M(кандидат)` менше за еталон рівно на ці 2 пари.
5. Усі учасники порівняння (worker-и й еталон) виконані в одному K.

Прямий наслідок для X_full: `R = R_sel ⊎ X_full` для гілок режиму `-Suite`
(root-inline перевірки Full дорівнюють root-інстансам вибіркового прогону плюс
X_full; за `02-COVERAGE-AUDIT.md`, статично). Тому union `-Suite` прогонів без
носія X_full не еквівалентний Full.

Чого модель не стверджує: вона не доводить еквівалентність, лише формулює
критерій. Еквівалентність залишається непідтвердженою (NOT RUN): на
`3d441d4e` є один Full, порівняння кількох прогонів на одному (sha, K)
відсутнє. Пороги стабільності (кількість пар Full/паралель, SHA, діб) це
рішення власника OD-18, тут не фіксуються.

| Структурований артефакт результату | OD-06 (відкрито) |
